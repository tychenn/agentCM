# Agent 轨迹生长与子图压缩动画

这是一个可离线打开、可修改的网页动画。案例来自上一级目录的 `trajectory.json`：主 Agent 处理 17 份文件，经过 14 个回合、28 次工具调用完成文档分类和发票汇总。动画将这些回合分成 6 个子任务，并编排 **4 次叶子子图压缩 + 1 次高层归并**。

完成 step 12 的最后一批 JPG 核对后，动画先将 JPG 子图压缩，再将 PDF 与 JPG 两个已压缩子图合并为“全部文档判定结果”。这个二级摘要保留 10 份发票的文件名、含税总额、VAT，以及 7 份其他文档的文件名，每条记录均标出来自 step 6～12 的证据。随后 step 13 使用这些结果执行归档和 CSV 汇总。

## 打开与操作

[在线播放](https://tychenn.github.io/agentCM/)无需下载。页面底部可以打开完整事件记录或下载关键帧材料包。

直接双击本目录的 **`index.html`**，用浏览器打开即可。播放无需安装依赖、启动服务或联网；现成的 `data.js` 已包含本案例所需的数据。

- **从零播放 / 暂停 / 继续播放**：观看轨迹逐步生成。
- **上一步 / 下一步**：按任务开始、回合计划、工具调用、反馈、叶子压缩、高层归并等事件移动。
- **拖动进度条、点击章节或跳到完成**：定位到指定阶段。
- **速度**：切换 0.5× 至 3×。
- **点击回合节点**：查看当前已出现的命令与原始记录。
- **展开子图 / 恢复压缩**：检查压缩摘要对应的原始回合。展开二级摘要时先看到 PDF 与 JPG 两个子摘要，再展开对应子图即可查看其原始回合。恢复播放或重新定位时，会恢复该时刻的预设压缩状态。
- **重播**：回到空白轨迹图。

## 修改动画

| 文件 | 修改内容 |
| --- | --- |
| `storyboard.json` | 中文文案、子任务分组、逐文件记录、候选依赖及其证据、叶子压缩和高层归并时点 |
| `app.js` | 动画逻辑与图布局；顶部 `TIMING` 控制各类事件持续秒数 |
| `styles.css` | 字体、颜色、页面尺寸与响应式布局 |
| `index.html` | 页面标题、布局与固定界面文字 |
| `build_data.py` | 将原始轨迹与分镜配置合并为播放数据，并检查基本结构 |
| `data.js` | 自动生成的播放数据；修改分镜后重新生成 |

修改 `storyboard.json` 后，在本目录运行下面的命令，再刷新浏览器：

```sh
python3 build_data.py
```

当前电脑的系统 Python 如提示 Xcode 许可问题，可使用已验证可用的 Codex 内置 Python：

```sh
"/Users/tianyu/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3" build_data.py
```

构建只写入 `data.js`，不会修改原始 `trajectory.json`，也不会执行轨迹里记录的命令。它会检查回合覆盖、分组、依赖端点和压缩时点；每次叶子压缩必须安排在对应子任务全部回合完成之后。高层归并还要求子任务存在、唯一且互不重叠，所有子任务都已完成并已压缩。事实与依赖含义仍需人工核对。

`higherGroups` 描述高层摘要，包括 `memberGroupIds`、摘要、保留信息和 `records`；构建器根据子任务派生 `stepIds` 与 `level: 2`。`records.invoices` 使用两位小数的字符串保存金额，`records.other` 保存其他文件，两类记录都用 `evidenceStepId` 指向原始证据。`merges` 设置归并时点。当前 JPG 压缩与高层归并均设为 `afterStep: 12`，播放器依次执行“回合反馈 → 叶子压缩 → 高层归并”，再进入 step 13。动画时长随 `app.js` 中的 `TIMING` 自动计算。

若更换源文件，可以通过 `--source` 指定路径；新的 `storyboard.json` 需要与源轨迹回合一一对应。页面案例标题、固定统计与结尾文案也应一起核对。直接改动 `app.js`、`styles.css` 或 `index.html` 后刷新即可，无需重新生成数据。

## 数据与演示边界

可在本目录运行 `node tests/state.cjs` 检查播放状态与 SVG 结构，包括二级压缩、逐层展开、依赖证据保留、回退和中途暂停。该检查不覆盖浏览器的实际字体与布局。

- 回合的 `message`、工具调用、`observation` 和 `promptTokens` 来自原始轨迹。动画只在回合执行到相应阶段后展示调用和反馈。
- 子任务分组、摘要、依赖连线、4 个叶子压缩时点与 1 个高层归并时点均为人工编排。依赖标注有对应调用或输出依据，尚未通过自动建图或干预实验验证。
- 原始轨迹没有这些压缩或归并事件。网页中的压缩将图上的回合折叠为摘要，高层归并再将 PDF 与 JPG 子摘要收为一个二级摘要；两层均保留可展开的完整记录与对外连接。动画没有修改运行中 Agent 的上下文，也没有重新执行压缩后的 Agent。
- 图中的节点数变化不能代表 token 节省。`promptTokens` 是原始运行记录，包含运行框架开销；本动画没有测量压缩后的 token 数或任务效果。
- 高层摘要中的逐文件金额和分类依据 step 6～12 已可见的工具输出；后续 CSV 仅用于交叉核对。归并发生时，摘要不宣称 step 13 的归档或 CSV 写入已经完成。原始记录包含完成确认，未提供外部评分。
- 原始回合 3 的文字将 JPG 数量写为 10；动画采用文件清单中可核对的 **11 份 JPG + 6 份 PDF**。

## 分享给网页版 ChatGPT

`share-with-chatgpt/` 内包含按时间排序的 9 张实际浏览器关键帧、完整的 `execution-events.txt`，以及可独立播放的 `animation-standalone.html`。解压 `ChatGPT-Pro-upload.zip` 后，上传九张 JPG 和事件说明，让模型同时看到视觉变化和执行顺序；修改动画时再上传 `animation-source.txt`。具体提示在 `使用说明.txt`。

修改动画后，运行 `node export_for_chatgpt.cjs` 更新时间轴和独立网页，并依据生成的 `keyframes.json` 重新截图。网页支持 `?t=78.9` 这样的秒数链接，打开时自动暂停在指定位置。

## 发布到 GitHub Pages

`.github/workflows/trajectory-pages.yml` 在 `main` 的动画或轨迹数据更新后检查数据与播放状态，再发布动画和分享材料。首次发布需在仓库 Settings → Pages 将 Source 设为 **GitHub Actions**。发布网址为 `https://tychenn.github.io/agentCM/`，网站仅包含动画与分享材料。

公共网页可供别人直接播放。向 ChatGPT 提供网址时，也可附上页面底部的完整事件记录链接，供其按文字时间轴理解执行过程。
